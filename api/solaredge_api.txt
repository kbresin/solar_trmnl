SolarEdge Monitoring API V2 — Reference (verified against live responses, Nov 2026)
===================================================================================

V1 (monitoringapi.solaredge.com/site/...?api_key=) was retired 2026-11-03 and
returns HTTP 410. Everything below is V2.

Base URL:  https://monitoringapi.solaredge.com/v2
Auth:      Authorization: Bearer <access_token>   (OAuth "Site Access" app)
Format:    JSON
Times:     ISO 8601 with offset, e.g. 2026-11-09T00:00:00-06:00 (site-local)
Units:     energy WH, power W, temperature CELSIUS (each response says which)

Rate limits:
  - Short-window limit is tight: ~5 calls in a few seconds returned HTTP 429.
    api/v2_lib.sh retries 429s after 15s/30s/60s.
  - 2,000 credits/month on the free tier.

Implemented in api/v2_lib.sh (se_get / se_ensure_token).


AUTH
----

Authorize (browser, once):  https://connect.solaredge.com/authorize
  response_type=code, client_id, redirect_uri, scope="SITE_DATA DEVICE_DATA",
  access_duration=24 (months). Callback gets ?code=...&site_id=...
  Done by api/v2_authorize.sh.

Token:  POST /v2/oauth2/token   (JSON body, no redirect_uri)
  {grant_type:"authorization_code", code, client_id, client_secret}
  {grant_type:"refresh_token", refresh_token, client_id, client_secret}
  Returns access_token, refresh_token, token_type, expires_in (7200 s).
  The refresh token ROTATES on every refresh and expires after 14 days unused.
  Stored in ~/.local/state/solar_trmnl/tokens.json (mode 600).


ENDPOINTS USED IN THIS PROJECT
------------------------------

Site Details
  GET /sites/{siteId}
  .name, .peakPower, .location.timezone, .activationStatus, .lastUpdateTime

Site Energy
  GET /sites/{siteId}/energy
  Params: from, to (ISO 8601; default = today, local midnight to now),
          resolution (QUARTER_HOUR default, DAY, ...)
  QUARTER_HOUR supports a maximum window of 1 week.
  .unit = "WH", .values[] = {timestamp, value} (value null when no data)
  Used by: api/get_site_energy_today.sh (resolution=DAY)

Lifetime Energy
  GET /sites/{siteId}/lifetime-energy
  {"energy": 4.0582006E8, "unit": "WH", "lastUpdateTime": ...}
  Used by: api/get_site_energy_today.sh

Alerts
  GET /sites/{siteId}/alerts?only-open=true   (open only is also the default)
  Array; [] when nothing is open. Each alert:
    alertId, category (e.g. EQUIPMENT), type (e.g. CLOGGED_FAN), impact (int),
    status (OPEN/CLOSED), firstTrigger, lastTrigger, closeDate,
    component.{name, serialNumber}, errorCodes[]
  Used by: api/check4faults.sh

Inverter Status
  GET /sites/{siteId}/inverters/status
  Params: from, to (max 1 week at QUARTER_HOUR)
  .inverters.{SN}.{inverterMode, operationMode, powerLimit, temperature}
    each = {unit, values: [{timestamp, value}]}; most overnight slots are null.
  Note: production intervals report STARTING rather than MPPT in V2.
  Used by: api/check4faults.sh (fault modes, temperature)

Inverter Telemetry
  GET /sites/{siteId}/inverters/telemetry
  Params: from, to (max 1 week at QUARTER_HOUR)
  .inverters.{SN}.{power W, energy WH (per interval, NOT lifetime),
                   consumedAcPower, consumedAcEnergy, voltage, current, frequency}
  No dcVoltage in V2.
  Used by: api/check4faults.sh --full-check (weekly log)

Devices
  GET /sites/{siteId}/devices
  [{type:"INVERTER", serialNumber, name ("Inverter 1"), partNumber,
    nameplate, firmwareVersion, connectedOptimizers, active, ...}]

Not found in V2 (HTTP 404): /inventory, /inverters/power, /inverters/energy,
/inverters/production, /inverters/data.


INVERTER MODES (alert on the starred ones; see FAULT_MODES in check4faults.sh)
-------------------------------------------------------------------------------
  MPPT, SLEEPING, STARTING, THROTTLED, SHUTTING_DOWN, OFF, STANDBY — normal/benign
  FAULT *, LOCKED_FORCE_SHUTDOWN *, LOCKED_COMM_TIMEOUT *, LOCKED_INV_TRIP *,
  LOCKED_INV_ARC_DETECTED *, LOCKED_INTERNAL *
  LOCKED_STDBY, LOCKED_FIRE_FIGHTERS, LOCKED_DG, LOCKED_PHASE_BALANCER,
  LOCKED_PRE_COMMISSIONING — other locks
